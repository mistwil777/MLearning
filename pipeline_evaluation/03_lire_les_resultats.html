Définition

Calculer des métriques ne suffit pas — il faut savoir ce qu'elles signifient dans ton contexte précis, où le modèle se trompe, et pourquoi. Cette lecture est ce qui distingue un ingénieur ML d'un script qui tourne.

:::situation La Banque Postale — Modèle de scoring crédit

L'équipe livre un modèle avec accuracy=0.94 et F1=0.81. Le chef de projet valide. Trois mois plus tard, les analystes crédit remontent que le modèle refuse systématiquement les demandes de clients de moins de 30 ans avec peu d'historique — un profil qui était sous-représenté dans les données d'entraînement. L'accuracy globale était bonne, mais le modèle avait un angle mort entier. Une lecture sérieuse de la matrice de confusion par segment aurait détecté ça en 10 minutes. :::

Lire une matrice de confusion sur de vraies données

Voici ce qu'affiche sklearn sur un vrai problème de détection de fraude :

from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay
import matplotlib.pyplot as plt

cm = confusion_matrix(y_test, y_pred)
disp = ConfusionMatrixDisplay(confusion_matrix=cm, display_labels=["Normal", "Fraude"])
disp.plot(cmap="Blues")
plt.title("Matrice de confusion — Détection fraude")
plt.savefig("confusion_matrix.png")

Résultat affiché :
                 Prédit Normal    Prédit Fraude
Réel Normal          9 412              88
Réel Fraude            43              57

Comment lire ça ligne par ligne :

  • 9 412 transactions normales correctement identifiées — pas de problème
  • 88 transactions normales bloquées à tort — 88 clients innocents bloqués
  • 43 fraudes manquées — 43 fois où de l'argent a disparu sans alerte
  • 57 fraudes détectées — ce que le modèle fait bien

La question immédiate à poser : est-ce acceptable ?

{ } Code
Rappel sur les fraudes = 57 / (57 + 43) = 57%

Le modèle rate 43% des fraudes réelles.

Pour une banque, c'est probablement inacceptable. Le problème ne se voit pas dans l'accuracy globale (99.3%) — il se voit dans la matrice.

:::callout-insight Toujours regarder la matrice par classe, jamais seulement le chiffre global.

Un modèle peut avoir d'excellentes performances sur la classe majoritaire et être complètement inutile sur la classe minoritaire — celle qui t'intéresse le plus. L'accuracy globale cache systématiquement ce problème. :::

Décodage colonne par colonne :

  • precision 0.39 sur Fraude : quand le modèle dit "fraude", il a raison 39% du temps. 61% des alertes sont des fausses alarmes.
  • recall 0.57 sur Fraude : il détecte 57% des fraudes réelles. 43% passent inaperçues.
  • support 100 : il y a 100 vraies fraudes dans le jeu de test.
  • weighted avg : moyenne pondérée par le nombre d'exemples — dominée par "Normal" (9500 cas). Ce chiffre est trompeur ici.
  • macro avg : moyenne simple des deux classes — plus honnête sur les classes déséquilibrées.

:::warning Ne jamais regarder seulement "accuracy" et "weighted avg" sur un dataset déséquilibré. Ces deux chiffres sont dominés par la classe majoritaire. La ligne qui compte, c'est celle de la classe rare — celle que tu veux détecter. :::

Lire l'importance des features

L'importance des features te dit sur quoi le modèle s'appuie réellement pour décider. C'est indispensable pour deux raisons : vérifier que le modèle utilise des informations légitimes, et détecter un data leakage.

import pandas as pd
import matplotlib.pyplot as plt

# Récupérer les importances depuis le modèle entraîné
feature_names = num_features + list(
    pipeline.named_steps["preprocessing"]
    .named_transformers_["cat"]
    .named_steps["encoder"]
    .get_feature_names_out(cat_features)
)

importances = pipeline.named_steps["modele"].feature_importances_

# Trier et afficher
df_imp = pd.DataFrame({"feature": feature_names, "importance": importances})
df_imp = df_imp.sort_values("importance", ascending=True).tail(15)

df_imp.plot(kind="barh", x="feature", y="importance", figsize=(10, 6), legend=False)
plt.title("Importance des features")
plt.xlabel("Importance relative")
plt.tight_layout()
plt.savefig("feature_importance.png")

Les questions à se poser sur chaque feature importante :

  1. C'est logique métier ? Si "montant" est en tête, c'est cohérent — les grosses transactions sont plus ciblées. Si "id_client" est en tête, c'est un data leakage — le modèle a mémorisé des clients spécifiques.

  2. Cette information sera disponible en production ? Si tu utilises "résultat_enquête" comme feature pour prédire la fraude, cette info n'existe pas encore au moment de la décision. Leakage.

  3. La feature la plus importante est-elle légitime ? Une importance très dominante (>60%) sur une seule feature mérite investigation — le modèle est peut-être trop dépendant d'une variable fragile.

Analyser où le modèle se trompe — par segment

La matrice globale ne suffit pas. Il faut regarder les erreurs par sous-groupe.

import pandas as pd

# Créer un dataframe avec les prédictions et les vraies valeurs
results = X_test.copy()
results["y_true"] = y_test.values
results["y_pred"] = y_pred
results["correct"] = results["y_true"] == results["y_pred"]

# Performance par tranche d'âge
results["age_groupe"] = pd.cut(results["age"], bins=[0, 25, 35, 50, 100],
                                labels=["<25", "25-35", "35-50", ">50"])

perf_par_age = results.groupby("age_groupe").agg(
    n_cas=("correct", "count"),
    taux_correct=("correct", "mean"),
    n_fraudes_reelles=("y_true", "sum"),
    n_fraudes_detectees=("y_pred", "sum"),
).round(3)

print(perf_par_age)

Le diagnostic complet en 5 questions

Après avoir entraîné un modèle, parcours systématiquement ces 5 questions avant de conclure :

{ } Code
1. Accuracy globale → est-elle trompeuse (classes déséquilibrées) ?
   → Si oui, regarder F1 et AUC-ROC

2. Matrice de confusion → combien de FN et FP ?
   → FN coûteux (fraude, maladie) → optimiser le rappel
   → FP coûteux (spam, blocage client) → optimiser la précision

3. Importance des features → les top features sont-elles légitimes ?
   → Chercher un data leakage sur toute feature avec importance > 40%

4. Performance par segment → y a-t-il un sous-groupe mal couvert ?
   → Découper par âge, région, période, type de client

5. Erreurs concrètes → regarder les exemples mal classés
   → Lire 10-20 faux négatifs pour comprendre ce que le modèle rate

Regarder les exemples mal classés

# Les faux négatifs — fraudes manquées par le modèle
faux_negatifs = results[
    (results["y_true"] == 1) & (results["y_pred"] == 0)
].head(10)

print("Fraudes manquées :")
print(faux_negatifs[["montant", "heure", "age", "pays"]].to_string())

Lire ces exemples manuellement révèle souvent un pattern : les fraudes manquées ont peut-être un petit montant (atypique pour une fraude), ou proviennent d'un pays jamais vu en entraînement. C'est une information que les métriques globales ne donnent jamais.

Flashcards

La matrice de confusion affiche 43 faux négatifs sur 100 fraudes réelles. Quel est le rappel ?

Voir la réponse
Réponse

Rappel = VP / (VP + FN) = 57 / (57 + 43) = 57%. Le modèle rate 43% des fraudes réelles — probablement inacceptable pour une banque.

Dans un rapport de classification, "weighted avg f1 = 0.99" sur un dataset avec 99% de cas normaux. Est-ce un bon signe ?

Voir la réponse
Réponse

Non — le weighted avg est dominé par la classe majoritaire (99% des cas). Il masque les performances sur la classe rare. Il faut regarder la ligne "Fraude" séparément, pas la moyenne pondérée.

Comment détecter un data leakage via l'importance des features ?

Voir la réponse
Réponse

Une feature avec importance très élevée (>50%) qui n'a pas de sens métier, ou une feature qui contient une information du futur (résultat d'enquête, montant remboursé...) est suspecte. AUC proche de 1.0 sans raison évidente → chercher un leakage.

Pourquoi analyser les performances par segment (âge, région...) et pas seulement globalement ?

Voir la réponse
Réponse

Un modèle peut être excellent en moyenne et avoir un angle mort complet sur un sous-groupe sous-représenté dans les données d'entraînement. La métrique globale cache ces inégalités — seule l'analyse par segment les révèle.

Tu regardes les faux négatifs d'un modèle de fraude et tu constates qu'ils ont tous un montant < 50€. Qu'est-ce que ça t'apprend ?

Voir la réponse
Réponse

Le modèle ne détecte pas les petites fraudes. Probablement parce que les données d'entraînement contenaient peu de fraudes à faible montant, ou parce qu'une feature "montant" est trop dominante. Action : rééquilibrer le dataset ou ajuster le seuil de décision.
