Évaluer un modèle : choisir la bonne métrique

Programme7 jours3-4h/jour

Pourquoi les métriques sont cruciales — et pourquoi l'accuracy ment

Définition de l'accuracy (précision globale) : la proportion d'exemples correctement classifiés. C'est la métrique la plus intuitive.

{ } Code
accuracy = (exemples correctement classifiés) / (total d'exemples)

Le problème : l'accuracy est trompeuse dès que les classes sont déséquilibrées. Si 98% des transactions bancaires sont normales et 2% sont frauduleuses, un modèle qui dit "normal" à chaque fois obtient 98% d'accuracy — en ne détectant aucune fraude.

Ce phénomène s'appelle le paradoxe des classes déséquilibrées et il touche tous les problèmes de détection (fraude, maladie, panne, spam) où les cas positifs sont rares.

Les quatre cases de la réalité : la matrice de confusion

Définition de la matrice de confusion : un tableau 2×2 qui récapitule les quatre résultats possibles d'une prédiction binaire.

{ } Code
                        Réalité
                   FRAUDE    NORMAL
Prédiction  FRAUDE   VP        FP    ← le modèle dit "fraude"
            NORMAL   FN        VN    ← le modèle dit "normal"

VP = Vrai Positif  : fraude réelle, détectée comme fraude       ← on veut maximiser
FP = Faux Positif  : normal, déclaré fraude par erreur          ← coûteux (client innocent bloqué)
FN = Faux Négatif  : fraude réelle, manquée par le modèle       ← dangereux (perte d'argent)
VN = Vrai Négatif  : normal, correctement identifié comme normal

Précision et Rappel : le dilemme fondamental

Définition de la précision (Precision) : parmi toutes les alertes levées par le modèle, quelle proportion est réellement une fraude ?

{ } Code
Précision = VP / (VP + FP)

Définition du rappel (Recall, aussi appelé sensibilité) : parmi toutes les vraies fraudes, quelle proportion le modèle a-t-il détectée ?

{ } Code
Rappel = VP / (VP + FN)

Le dilemme : augmenter l'un diminue l'autre. Si le modèle est très prudent (lève une alerte sur le moindre doute), il détecte plus de fraudes (rappel élevé) mais lève aussi plus de fausses alertes (précision basse). Si le modèle est très sélectif (n'alerte que quand il est très sûr), il a peu de fausses alertes (précision élevée) mais rate des fraudes (rappel bas).

La question à poser au métier : "Qu'est-ce qui coûte le plus cher — bloquer un client innocent ou rater une fraude ?"

Cas Priorité Métrique à maximiser
Détection de cancer Ne pas manquer un cas → rappel élevé Rappel (un faux négatif = patient non traité)
Filtre anti-spam Ne pas bloquer les vrais emails → précision élevée Précision (un faux positif = email légitime perdu)
Fraude bancaire Équilibre F1-score

F1-score : la moyenne harmonique expliquée

Définition du F1-score : la moyenne harmonique de la précision et du rappel. Elle donne une note unique qui pénalise fortement si l'une des deux métriques est nulle.

{ } Code
F1 = 2 × (Précision × Rappel) / (Précision + Rappel)

Pourquoi la moyenne harmonique et pas la moyenne arithmétique ? Si un modèle a précision=1.0 et rappel=0.0 (il ne prédit jamais "fraude"), la moyenne arithmétique serait 0.5 — trompeur. La moyenne harmonique donne 0.0 — ce modèle est inutile. La moyenne harmonique punit sévèrement les déséquilibres extrêmes.

AUC-ROC : intuition géométrique

Définition de l'AUC-ROC : l'Aire Sous la Courbe ROC (Receiver Operating Characteristic). La courbe ROC trace le taux de vrais positifs (rappel) en fonction du taux de faux positifs, pour tous les seuils de décision possibles. L'AUC est l'aire sous cette courbe.

Intuition : l'AUC mesure la capacité du modèle à ordonner correctement les exemples — à mettre les fraudes en tête de liste et les transactions normales à la fin. Elle ne dépend pas d'un seuil fixe.

{ } Code
AUC = 0.5 → modèle aléatoire (inutile — pire que de lancer une pièce)
AUC = 0.7 → acceptable en production
AUC = 0.8 → bon modèle
AUC = 0.9 → excellent modèle
AUC = 1.0 → modèle parfait (suspect — probablement du data leakage)

Définition du data leakage : une information du futur qui s'est glissée dans les features d'entraînement. Exemple : inclure le "montant remboursé" comme feature pour prédire si le crédit sera remboursé — le modèle "sait" déjà la réponse. AUC proche de 1.0 sans raison évidente → chercher un leakage.

RMSE et MAE pour la régression

Pour les problèmes de régression (prédire un nombre), les métriques sont différentes :

Définition du RMSE (Root Mean Squared Error) : la racine carrée de la moyenne des erreurs au carré. Pénalise fortement les grosses erreurs.

{ } Code
RMSE = √( (1/n) × Σ(réel - prédit)² )

Définition du MAE (Mean Absolute Error) : la moyenne des valeurs absolues des erreurs. Traite toutes les erreurs également.

{ } Code
MAE = (1/n) × Σ|réel - prédit|

Le RMSE pénalise plus les grosses erreurs que les petites. Si une prédiction à 100 000€ d'écart est catastrophique (valeur d'une maison), utiliser le RMSE. Si toutes les erreurs ont le même impact (prédiction de consommation électrique heure par heure), utiliser le MAE.

Tableau de décision : quel problème → quelle métrique

Problème Métrique recommandée Pourquoi
Fraude bancaire (2% positifs) AUC-ROC, F1, Rappel Classes très déséquilibrées — accuracy inutile
Scoring crédit (probabilité) AUC-ROC On veut ordonner les risques, pas juste classer
Spam / pas spam Précision (ou F1) Faux positifs coûteux (email légitime bloqué)
Diagnostic médical Rappel Faux négatifs catastrophiques (maladie non détectée)
Prévision de prix RMSE (grosses erreurs coûteuses) ou MAE Selon le coût métier des grandes erreurs
Classification multi-classes équilibrées Accuracy, F1 macro Classes équilibrées → accuracy fiable 
from sklearn.metrics import (
    accuracy_score, precision_score, recall_score,
    f1_score, roc_auc_score, classification_report,
    mean_squared_error, mean_absolute_error
)
import numpy as np

# Pour un problème de classification
y_pred = pipeline_complet.predict(X_test)
y_proba = pipeline_complet.predict_proba(X_test)[:, 1]

print(f"Accuracy  : {accuracy_score(y_test, y_pred):.3f}")
print(f"Précision : {precision_score(y_test, y_pred):.3f}")
print(f"Rappel    : {recall_score(y_test, y_pred):.3f}")
print(f"F1-score  : {f1_score(y_test, y_pred):.3f}")
print(f"AUC-ROC   : {roc_auc_score(y_test, y_proba):.3f}")

print("\n--- Rapport complet ---")
print(classification_report(y_test, y_pred, target_names=['Normal', 'Fraude']))

# Pour un problème de régression
from sklearn.metrics import mean_squared_error, mean_absolute_error
rmse = np.sqrt(mean_squared_error(y_test_reg, y_pred_reg))
mae = mean_absolute_error(y_test_reg, y_pred_reg)
print(f"RMSE : {rmse:.1f} €")
print(f"MAE  : {mae:.1f} €")
Flashcards

Un modèle de détection de fraude affiche 99% d'accuracy sur un dataset où 1% des transactions sont frauduleuses. Est-ce un bon modèle ?

Voir la réponse
Réponse

Non — paradoxe des classes déséquilibrées. Un modèle qui dit "normal" à chaque fois obtient 99% d'accuracy sans détecter une seule fraude. Les métriques pertinentes sont le rappel (fraudes détectées / total vraies fraudes) et l'AUC-ROC.

La précision est à 0.95 et le rappel à 0.30. Que signifient ces chiffres pour un détecteur de fraude ?

Voir la réponse
Réponse

95% des alertes levées sont de vraies fraudes (peu de fausses alarmes — bonne précision), mais le modèle ne détecte que 30% des fraudes réelles (70% passent inaperçues — rappel catastrophique). Ce modèle est inutile en pratique : il rate 7 fraudes sur 10.

Pourquoi la moyenne harmonique (F1) plutôt que la moyenne arithmétique ?

Voir la réponse
Réponse

Si précision=1.0 et rappel=0.0, la moyenne arithmétique donne 0.5 (trompeur). La moyenne harmonique donne 0.0 (correct — ce modèle ne prédit jamais la classe positive). La F1 punit fortement les déséquilibres extrêmes entre précision et rappel.

Un modèle de prédiction de prix de maison a RMSE=15 000€ et MAE=8 000€. Que signifie l'écart RMSE > MAE ?

Voir la réponse
Réponse

L'écart signifie qu'il existe quelques grosses erreurs qui tirent le RMSE vers le haut (le RMSE pénalise les écarts au carré). La plupart des prédictions ont une erreur ≈ 8 000€ (MAE), mais certaines ont des erreurs bien supérieures — des cas atypiques mal prédits.
